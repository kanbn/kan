---
title: Custom fields
description: "Add structured, board-specific information to cards."
---

Custom fields let a board define structured information that does not fit a
label, member or due date. You can use them for a workflow status, customer
reference, story points, review date or yes/no flag.

## Create and manage fields

Open **Board options**, then select **Custom fields**. You can also use the edit
button beside **Custom fields** on a card. Board editors can create, reorder and
delete fields and configure how each field is displayed.

Fields are collapsed by default. Open a field to edit its settings, then choose
**Save** to apply the complete configuration or **Cancel** to discard the
draft.

Kan supports the following field types:

| Type     | Use it for                                |
| -------- | ----------------------------------------- |
| Text     | Names, references and short notes         |
| Number   | Estimates, costs and other numeric values |
| Date     | Dates and times                           |
| Checkbox | Yes/no or complete/incomplete values      |
| Choice   | One value from a list you define          |

For a choice field, **Options** are the values that card editors can choose.
Each option has a name and order. Colour is optional; when it helps distinguish
values, choose one from the same palette used by labels. Imported colours that
are outside that palette remain intact until you replace or remove them. For
example, a `Status` field might offer `Planned`, `In progress`, `Blocked` and
`Done`.

Deleting a field removes it from the board and its cards. Archiving a choice
option prevents new assignments without deleting values already stored on
cards.

## Descriptions, input hints and defaults

A field description explains how the field should be used and appears with the
field on card forms. Text and number fields can also have a short **Input hint**
inside an empty input. The hint is not a card value.

A default value is applied when a new card is created. Card editors can replace
the suggested value or deliberately leave the field empty. Changing a default
does not update existing cards.

## Choose where fields appear

Use **Placement** to show a field in the card's **Main panel** or **Sidebar**.
An optional **Section** groups related fields under a shared heading. Sections
are flat: a field belongs to at most one named section, and sections cannot be
nested.

**Show on card front** is independent from placement. Enable it when a populated
value should also appear on cards in the board view.

On mobile, main-panel fields remain in the card body. Sidebar fields are
available from the card's settings drawer.

## Set values on a card

Open a card and edit its custom fields in the configured main or sidebar
section. Changes are saved using the same inline editing behaviour as other card
details. Checkbox fields are either checked or unchecked; unchecking one clears
its stored value.

Custom fields also appear while creating a card. Defaults are prefilled, and
you can replace or clear them before adding the card.

## Filter a board

Open **Filter**, choose **Custom fields**, then choose a field to limit the
visible cards. Choice and checkbox fields offer their available values. Text,
number and date fields offer controls appropriate to their type. Custom-field
conditions combine with the board's other active filters.

## Duplicate, move and import

Card duplication can copy custom-field values. Board templates copy field
definitions, choice options, defaults and values. Moving a populated card to
another board preserves its values by reusing compatible target fields or
creating an explicit mapping.

The Trello importer brings across supported definitions, choice options,
card-front visibility and current card values. Trello does not provide Kan's
placement, section or default metadata, so imported fields start in the sidebar
without a section or default. You can configure those properties after import.
